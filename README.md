# Korochin PageShot

[English](README.en.md)

Chrome / Edge でWebページを撮影する Manifest V3 拡張です。撮影した画像をPNGで保存したり、クリップボードへ直接コピーしたりできます。短い動きはWebP / PNGの連番画像としてZIPに、タブの音声はWebM音声として保存できます。タブバーやアドレスバーなど、ブラウザの外枠は写りません。ビルドや npm install は不要です。

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| 表示中の領域をPNG保存 | Ctrl + Shift + Y | Command + Shift + Y |
| ページ全体をPNG保存 | Ctrl + Shift + U | Command + Shift + U |
| 表示中の領域をコピー | Alt + Shift + Y | Option + Shift + Y |
| ページ全体をコピー | Alt + Shift + U | Option + Shift + U |
| ページタイトルをコピー | 要設定 | 要設定 |
| コマ送り画像をZIP保存 | 要設定 | 要設定 |

ブラウザにフォーカスがある状態で使います。画像コピー用のショートカットを押すと、ポップアップや保存ダイアログを開かずに、撮影したPNGをクリップボードへコピーします。「ページタイトルをコピー」では表示中のページの `document.title` をテキストとしてコピーします。各操作は拡張アイコンのポップアップからも実行できます。

## インストール

1. Chrome では `chrome://extensions/`、Edge では `edge://extensions/` をアドレスバーに入力します。
2. 「デベロッパー モード」（Edge は「開発者モード」）を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」（Edge は「展開して読み込み」）を選びます。
4. この README と `manifest.json` がある **korochin-pageshot フォルダ**を指定します。
5. 必要に応じて、拡張メニューから PageShot をツールバーに固定します。
6. 通常のWebページを開き、ショートカットかポップアップのボタンで撮影します。

Chrome / Edge 118 以降を対象にしています。ソース更新後は拡張管理画面の再読み込みボタンを押してください。

## 保存先とコピー結果

ブラウザで設定したダウンロードフォルダ内の `screenshots` に保存します。

```text
screenshots/
├─ screenshot-viewport-20260909-152130-042.png
└─ screenshot-fullpage-20260909-152135-108.png
```

ファイル名の日時はPCのローカル時刻です。同名のファイルがある場合はブラウザが連番を付けるため、既存ファイルを上書きしません。拡張から保存ダイアログは要求しませんが、ブラウザ設定や管理ポリシーによっては表示される場合があります。

アイコンのバッジは処理の状態を示します。`…` は処理中、`WAIT` は撮影開始待ち、`REC` は連続撮影中または音声録音中（録音時は赤色）、`↓` はダウンロード開始、`✓` はクリップボードへのコピー完了、`!` は失敗です。結果の詳細はアイコンを押して確認できます。`↓` は保存完了を保証する表示ではありません。保存の完了や中断はブラウザのダウンロード一覧（Windows は Ctrl + J）で確認してください。

## タブの音声録音

1. 音声を再生するタブで拡張アイコンを押し、「タブの音声」の「録音開始」を押します。
2. 録音中は赤色の `REC` バッジと、メニュー内の経過時間を表示します。メニューを閉じたり別のタブへ移ったりしても、開始時のタブを録音し続けます。音声は録音中も聞こえます。
3. 拡張アイコンをもう一度押し、「録音を停止して保存」を押します。ダウンロード / screenshots に `audio-日時.webm` を保存します。日時は録音開始時刻です。

形式はWebM / Opus（目標128kbps）です。マイク、他のタブ、他のアプリの音声は含みません。音が出ていない時間は無音として録音されます。通常のWebページで使用してください。ブラウザの内部ページや保護されたコンテンツなどは録音できない場合があります。

保存時には音声フレームの時刻と長さから再生時間を計算し、WebMの時間情報に書き込みます。これにより、アップロード先が再生時間を不明と判定する問題を防ぎます。音声は再圧縮しません。時間情報を補完できない場合も元の録音を保存し、結果に警告を表示します。

タブを閉じるなどして共有が終了すると、それまでの音声を保存します。メモリ使用量を抑えるため、60分または128MBに達した時点でも自動停止して保存します。録音中は他の撮影・コピーを開始できません。ブラウザを終了したり拡張を再読み込みしたりする前に停止・保存してください。保存前の録音はメモリ上にあり、ブラウザ終了後には復元できません。

## コマ送り画像

短い動きを連番画像にして、AIへ動きの参考として渡せます。

1. 撮影するタブで拡張アイコンを押し、「コマ送り画像」の設定を選びます。初期設定は **3秒・10fps・WebP・最大幅1280px** です。
2. 「2秒後に連続撮影」を押すとメニューが閉じ、2秒のカウントダウン後に撮影が始まります。対象のアニメーションやスクロールを操作してください。
3. 指定した時間が経つと撮影が自動で終了し、ダウンロード / screenshots に screenshot-sequence-日時.zip を保存します。
4. 途中で終える場合は拡張アイコンをもう一度開き、「途中で停止して保存」を押します。カウントダウン中はキャンセルできます。

撮影時間は1 / 2 / 3 / 5 / 10秒、目標fpsは2 / 5 / 10、形式はWebP / PNG、最大幅は960 / 1280 / 1920pxから選べます。選んだ設定は次回の撮影やショートカットからの実行にも使われます。

ZIPには次のファイルとフォルダが入ります。

- frames/：連番画像。ファイル名にコマ番号と撮影開始からの経過時間をミリ秒で含みます。
- sheets/：左から右、上から下へ10コマずつ並べた時刻付きの一覧画像。形式はWebP、品質は0.82、配置は2列×最大5行です。連番画像にPNGを選んだ場合も、一覧はWebPで保存します。
- manifest.json：ページタイトル・URL、撮影設定、各コマの実際の切り出し時刻、画像サイズ、終了理由。
- README.txt：画像の読み方。

AIにはまず一覧画像を渡し、必要なコマの原画像を追加すると細部を確認しやすくなります。ローカルファイルを扱えるエージェントなら、ZIPを展開したフォルダの場所を伝えられます。

撮影対象は開始時に選んだタブの表示領域です。音声・画面外のページ全体・操作ログは含みません。WebPは品質0.82の非可逆圧縮、PNGは可逆圧縮です。画像の幅が指定値を超えるか、高さが1920pxを超える場合だけ、縦横比を保って縮小します。撮影中にタブをリサイズすると固定サイズの画像内に余白が入る場合があります。

fpsは目標値です。負荷やブラウザの描画状況によってはコマが抜けたり重複したりします。各コマの時刻も動画の厳密なフレーム時刻ではありません。撮影が遅れた分のコマをまとめて撮ることはせず、manifest.jsonのelapsedMsに実際の切り出し時刻を記録します。

撮影中は対象タブを表示し、ウィンドウを最小化しないでください。タブの共有が終了した場合は、取得済みの画像を保存します。連番画像が128MBを超えた場合は、メモリを保護するためエラーで終了します。

## ショートカットの変更

ポップアップの「ショートカットを変更」、または以下の画面で変更できます。

- Chrome: `chrome://extensions/shortcuts`
- Edge: `edge://extensions/shortcuts`

他の拡張やOSと競合すると、初期ショートカットが登録されないことがあります。ポップアップに「未設定」と出た場合は、この画面で割り当ててください。ポップアップには実際に割り当てられたショートカットが表示されます。

Chromiumでは、拡張機能が初期値を指定できるショートカットは4個までです。そのため、「ページタイトルをコピー」「コマ送り画像をZIP保存」には初期キーを設定していません。上記の画面で任意のキーを割り当ててください。

## 撮影方式と制約

- 表示領域: `chrome.tabs.captureVisibleTab()` を使い、現在のスクロール位置で見えているページの部分を保存します。
- コマ送り画像: tabCaptureでタブの映像をoffscreenドキュメントへ渡し、Canvasで画像へ変換します。通常のcaptureVisibleTabにある毎秒2回の制限を受けず、ページに撮影UIを挿入しません。追加の外部ライブラリは使用しません。
- ページ全体: 撮影するタブに `chrome.debugger` で一時的に接続し、`Page.getLayoutMetrics` の `cssContentSize` を `Page.captureScreenshot` の `clip` に指定します。横方向・縦方向の画面外も含みます。ブラウザのズームが100%以外の場合は、画面ごとに撮影範囲を重ねて撮影し、画像を結合して拡大率による画像の反復を避けます。100%で短いページや表示の反復が検出されたページでは、サイズ制限内なら一時的に表示領域をページ全体の高さへ広げて撮影を試します。この方法が使えない場合は、順にスクロールして表示領域を重ねて撮影し、画像を結合します。終了後は元の表示領域とスクロール位置に戻します。
- 全体撮影中、ブラウザ上部にデバッグ接続の通知が出ます。開発者ツールや別のデバッグ拡張と競合する場合は、それらを閉じてから撮影してください。
- 遅延読み込みの画像は先にスクロールして読み込んでください。無限スクロールでまだ取得していない内容、仮想リストでDOMに存在しない行、独立したスクロール枠の内部全体は自動で展開しません。
- 非常に長いページは、ブラウザの画像サイズ・メモリ制限により失敗する場合があります。その場合は表示領域の撮影を利用してください。
- 動画・アニメーション・固定要素・動的レイアウトの写り方は、ブラウザのレンダリングに依存します。
- 再撮影へは自動で切り替わります。分割撮影中はページのスクロール位置が一時的に変わり、固定表示の要素が複数箇所に写る場合があります。ページ自体を必要な位置までスクロールできない場合はエラーを表示します。
- ブラウザの内部ページ、拡張ストア、PDFビューアーなどは撮影方式によって制限があります。まず通常の HTTP / HTTPS ページで使用してください。ローカルHTMLは拡張の詳細画面で「ファイルの URL へのアクセスを許可する」を有効にします。
- 連打しても処理が重複しないようにしています。表示領域を撮影するには、APIの回数制限に合わせて600ミリ秒以上の間隔を空ける必要があります。

## 権限とデータ

| 権限 | 用途 |
| --- | --- |
| activeTab | ユーザー操作時のタブで表示領域を撮影 |
| clipboardWrite | 撮影したPNGまたはページタイトルをクリップボードに書き込み |
| downloads | PNG・連番画像ZIP・WebM音声をダウンロードフォルダへ保存 |
| tabCapture | ユーザー操作で開始したタブの映像からコマ送り画像を作成し、音声を録音 |
| debugger | ページ全体のキャプチャ |
| offscreen | 反復画像の検出・結合、連続撮影と一覧画像・ZIP作成、音声録音と録音中の音声再生 |
| scripting | ショートカットを使ったとき、アクティブなページで画像・タイトルのクリップボードAPIを実行 |
| storage | 実行結果と保存中のZIP・音声への参照をセッションに保持し、連続撮影の設定をローカルに保存 |

`debugger` は強い権限で、インストール時にブラウザが警告を表示します。この権限は撮影操作時だけ使用します。外部サーバーへの通信、解析サービス、常駐コンテンツスクリプトはありません。

画像はダウンロードAPIまたはOSのクリップボードに渡し、履歴ストレージには保存しません。連続撮影のZIPと録音した音声は、ダウンロードが完了するか中断されるまで一時的にメモリ上に保持します。ZIP内の撮影情報にはページタイトルとURLも含まれます。

## 検証

Node.js 18 以降で実行できます。外部の依存パッケージは不要です。

```powershell
npm.cmd test
npm.cmd run check
```

自動テストではAPIをモックに置き換え、撮影モードの分離、対象ウィンドウ、CSS寸法、反復の検出、分割範囲と画像結合への切り替え、デバッグ接続の後始末、連打・並行実行、保存エラーを検証します。連続撮影では、目標間隔と負荷が高いときのコマの間引き、時刻付き一覧、途中停止、ZIP構造・CRC、保存に失敗したときのリソースの解放をモックで検証します。実際のブラウザでの画像品質は以下の手順で確認してください。

1. `tests/fixture.html` をブラウザで開き、ローカルファイルアクセスを許可します。
2. ページ途中までスクロールし、表示領域を撮影します。画像にブラウザ外枠や画面外の先頭・末尾がないことを確認します。
3. 同じ位置でページ全体を撮影します。画像に「START」「END」と右端のマーカーが含まれることと、撮影後も元のスクロール位置が保たれることを確認します。
4. ブラウザのズームを75%・125%に変更して両方撮影し、全体画像に同じ表示の反復・切れ・余白がないことを確認します。
5. 保存・コピーそれぞれのポップアップボタンとショートカットを試します。コピー後、画像を扱えるアプリへ貼り付けられること、異なるウィンドウでも対象が正しいことを確認します。
6. 「ページタイトルをコピー」にショートカットを割り当て、実行後にテキストエディターへ貼り付けると `PageShot キャプチャ確認ページ` になることを確認します。
7. 全体撮影が終わるとデバッグ通知が消えることと、撮影に失敗したときにポップアップに理由が出ることを確認します。

8. 動きのあるページで「3秒・10fps・WebP」を撮影し、ZIP内に約30枚の連番画像と3枚の一覧があり、順序・時刻・動きが対応することを確認します。通常のスクリーンショットと同時実行できないことも確認します。
9. PNGでの撮影、設定の変更、ショートカットでの実行、カウントダウン中のキャンセル、撮影途中の停止、対象タブを閉じた場合の動作を確認します。ポップアップを開き直しても設定が残ることと、撮影が終わるとタブの共有が解除されることを確認します。
10. `tests/audio-fixture.html` の「音を再生」を押し、拡張から録音を開始します。メニューを閉じて10秒ほど待ち、音が引き続き聞こえることと、開き直したメニューで経過時間と停止ボタンが表示されることを確認します。停止後のWebMを再生し、テスト音が録音され、マイクや他のタブの音声が入っていないことを確認します。
11. 録音中に別のタブへ移動して停止する場合、対象タブを閉じる場合、ブラウザの共有停止を使う場合も保存されることを確認します。30秒以上録音してサービスワーカーが休止した後も停止・保存でき、録音中の撮影・コピー用ショートカットが重複実行されないことを確認します。録音の自動テストではこれらの処理、時間・サイズ上限、録音・保存エラーとリソースの解放をモックで検証します。

## GitHub Releases用ZIP

ローカルでは次のコマンドで、拡張の実行に必要なファイルだけを含むZIPを生成できます。

```powershell
npm.cmd run package
```

出力先は `dist/korochin-pageshot-v1.3.1.zip` です。ZIPの最上位にはバージョン付きのフォルダがあります。展開後、Chrome / Edgeの「パッケージ化されていない拡張機能を読み込む」でそのフォルダを指定できます。`tests`、GitHub Actions、開発用ファイルは含みません。

GitHubでは `manifest.json` と同じバージョンのタグをpushすると、テストと構文チェックを実行し、ZIPを添付したReleaseを自動作成します。

```powershell
git tag v1.3.1
git push origin v1.3.1
```

タグと `manifest.json` のバージョンが一致しない場合、誤ったリリースを防ぐためワークフローは失敗します。次回リリース時は先に `manifest.json` と `package.json` のバージョンを同じ値へ更新してください。
