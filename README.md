# Korochin PageShot

Chrome / Edge のWebページをPNG保存、クリップボードへ直接コピー、または短い動きを連番WebP / PNGとしてZIP保存する Manifest V3 拡張です。タブバー、アドレスバーなど、ブラウザの外枠は入りません。ビルドや npm install は不要です。

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| 表示中の領域をPNG保存 | Ctrl + Shift + Y | Command + Shift + Y |
| ページ全体をPNG保存 | Ctrl + Shift + U | Command + Shift + U |
| 表示中の領域をコピー | Alt + Shift + Y | Option + Shift + Y |
| ページ全体をコピー | Alt + Shift + U | Option + Shift + U |
| ページタイトルをコピー | 要設定 | 要設定 |
| コマ送り画像をZIP保存 | 要設定 | 要設定 |

ブラウザにフォーカスがある状態で使います。画像コピー用ショートカットを押すと、ポップアップや保存ダイアログを開かず、撮影したPNGがそのままクリップボードに入ります。「ページタイトルをコピー」は表示中のページの `document.title` をテキストとしてコピーします。拡張アイコンのポップアップからも各操作を実行できます。

## インストール

1. Chrome では `chrome://extensions/`、Edge では `edge://extensions/` をアドレスバーに入力します。
2. 「デベロッパー モード」（Edge は「開発者モード」）を有効にします。
3. 「パッケージ化されていない拡張機能を読み込む」（Edge は「展開して読み込み」）を選びます。
4. この README と `manifest.json` がある **korochin-pageshot フォルダ**を指定します。
5. 必要に応じて、拡張メニューから PageShot をツールバーに固定します。
6. 通常のWebページを開き、ショートカットかポップアップのボタンで撮影します。

Chrome / Edge 118 以降を対象にしています。ソース更新後は拡張管理画面の再読み込みボタンを押してください。

## 保存先とコピー結果

ブラウザで設定したダウンロードフォルダ内の `screenshots` に保存します。

```text
screenshots/
├─ screenshot-viewport-20260909-152130-042.png
└─ screenshot-fullpage-20260909-152135-108.png
```

日時はPCのローカル時刻です。同名の場合はブラウザが連番を付けるため、既存ファイルを上書きしません。拡張から保存ダイアログは要求しませんが、ブラウザ設定や管理ポリシーによっては表示される場合があります。

アイコンのバッジは `…` が処理中、`WAIT` が撮影開始待ち、`REC` が連続撮影中、`↓` がダウンロード開始、`✓` がクリップボードへのコピー完了、`!` が失敗です。結果の詳細はアイコンを押して確認できます。`↓` は保存完了を保証する表示ではありません。保存の完了や中断はブラウザのダウンロード一覧（Windows は Ctrl + J）で確認してください。

## コマ送り画像（AIへ動きの参考を渡す）

1. 撮影するタブで拡張アイコンを押し、「コマ送り画像」の設定を選びます。初期設定は **3秒・10fps・WebP・最大幅1280px** です。
2. 「2秒後に連続撮影」を押すとメニューが閉じます。2秒のカウントダウン後に撮影するので、対象のアニメーションやスクロールを操作してください。
3. 指定時間で自動終了し、ダウンロード / screenshots に screenshot-sequence-日時.zip を保存します。
4. 途中で終える場合は拡張アイコンをもう一度開き、「途中で停止して保存」を押します。カウントダウン中はキャンセルできます。

撮影時間は1 / 2 / 3 / 5 / 10秒、目標fpsは2 / 5 / 10、形式はWebP / PNG、最大幅は960 / 1280 / 1920pxから選べます。設定は次回とショートカット実行時にも使われます。

ZIPの中身：

- frames/：連番画像。ファイル名にコマ番号と撮影開始からのミリ秒を含みます。
- sheets/：左から右、上から下へ10コマずつ並べた時刻付き一覧PNG（2列×最大5行）。
- manifest.json：ページタイトル・URL、撮影設定、各コマの実際の切り出し時刻、画像サイズ、終了理由。
- README.txt：画像の読み方。

AIにはまず一覧画像を渡し、必要なコマの原画像を追加すると細部を確認しやすくなります。ローカルファイルを扱えるエージェントなら、ZIPを展開したフォルダの場所を伝えられます。

対象は開始時に選んだタブの表示領域です。音声・画面外のページ全体・操作ログは含みません。WebPは品質0.82の非可逆圧縮、PNGは可逆圧縮です。画像は縦横比を保ち、指定幅か高さ1920pxを超える場合だけ縮小します。撮影中にタブをリサイズすると固定サイズの画像内に余白が入る場合があります。

fpsは目標値です。負荷やブラウザの描画状況によりコマの欠落・重複があり、厳密な動画フレーム時刻ではありません。遅れたコマをまとめて撮ることはせず、manifest.jsonのelapsedMsに実際の切り出し時刻を残します。撮影中は対象タブを表示し、ウィンドウを最小化しないでください。タブの共有が終了した場合は、取得済みの画像を保存します。連番画像が128MBを超えた場合はメモリ保護のためエラーで終了します。

## ショートカットの変更

ポップアップの「ショートカットを変更」、または以下の画面で変更できます。

- Chrome: `chrome://extensions/shortcuts`
- Edge: `edge://extensions/shortcuts`

他の拡張やOSと競合すると初期ショートカットが登録されないことがあります。ポップアップに「未設定」と出た場合は、この画面で割り当ててください。ポップアップには実際の割り当てが表示されます。

Chromiumでは拡張機能が初期値を指定できるショートカットが4個までのため、「ページタイトルをコピー」「コマ送り画像をZIP保存」には初期キーを設定していません。上記の画面で任意のキーを割り当ててください。

## 撮影方式と制約

- **表示領域**: `chrome.tabs.captureVisibleTab()` を使い、現在のスクロール位置で見えているページ部分を保存します。
- **コマ送り画像**: tabCaptureでタブの映像をoffscreenドキュメントへ渡し、Canvasで画像へ変換します。通常のcaptureVisibleTabの毎秒2回の制限にかからず、ページに撮影UIを挿入しません。追加の外部ライブラリは使用しません。
- **ページ全体**: 撮影するタブに `chrome.debugger` で一時接続し、`Page.getLayoutMetrics` の `cssContentSize` を `Page.captureScreenshot` の `clip` に指定します。横方向・縦方向の画面外も含みます。ブラウザのズームが100%以外の場合は、画面ごとに重ねて撮影・結合し、拡大率による画像の反復を避けます。100%で短いページや表示の反復が検出されたページでは、サイズ制限内なら一時的に表示領域をページ全体の高さへ広げた撮影を試します。これが使えない場合は、順にスクロールして表示領域を重ねて撮影・結合します。終了後は元の表示領域とスクロール位置に戻します。
- 全体撮影中、ブラウザ上部にデバッグ接続の通知が出ます。開発者ツールや別のデバッグ拡張と競合する場合は、それらを閉じてから撮影してください。
- 遅延読み込み画像は先にスクロールして読み込んでください。無限スクロールで未取得の内容、仮想リストでDOMに存在しない行、独立したスクロール枠の内部全体は自動展開しません。
- 非常に長いページは、ブラウザの画像サイズ・メモリ制限により失敗する場合があります。その場合は表示領域の撮影を利用してください。
- 動画・アニメーション・固定要素・動的レイアウトの写り方は、ブラウザのレンダリングに依存します。
- 再撮影への切り替えは自動です。分割撮影中はページのスクロール位置が一時的に変わり、固定表示の要素が複数箇所に写る場合があります。ページ自体を必要な位置までスクロールできない場合はエラーを表示します。
- ブラウザの内部ページ、拡張ストア、PDFビューアーなどは撮影方式によって制限があります。まず通常の HTTP / HTTPS ページで使用してください。ローカルHTMLは拡張の詳細画面で「ファイルの URL へのアクセスを許可する」を有効にします。
- 連打による重複処理を防ぎます。表示領域の撮影はAPIの回数制限に合わせて600ミリ秒以上の間隔が必要です。

## 権限とデータ

| 権限 | 用途 |
| --- | --- |
| activeTab | ユーザー操作時のタブで表示領域を撮影 |
| clipboardWrite | 撮影したPNGまたはページタイトルをクリップボードに書き込み |
| downloads | PNG・連番画像ZIPをダウンロードフォルダへ保存 |
| tabCapture | ユーザー操作で開始したタブの映像からコマ送り画像を作成 |
| debugger | ページ全体のキャプチャ |
| offscreen | 反復画像の検出・結合、連続撮影と一覧画像・ZIP作成 |
| scripting | ショートカット操作時のアクティブなページで画像・タイトルのクリップボードAPIを実行 |
| storage | 実行結果と保存中ZIPの参照をセッションに保持し、連続撮影の設定をローカルに保存 |

`debugger` は強い権限で、インストール時にブラウザが警告を表示します。撮影操作時だけ使用します。外部サーバーへの通信、解析サービス、常駐コンテンツスクリプトはありません。画像はダウンロードAPIまたはOSのクリップボードに渡し、履歴ストレージには保存しません。連続撮影のZIPはダウンロード完了・中断まで一時的にメモリ上に保持します。ZIP内の撮影情報にはページタイトルとURLも含まれます。

## 検証

Node.js 18 以降で、外部依存なしに実行できます。

```powershell
npm.cmd test
npm.cmd run check
```

自動テストではAPIをモックし、撮影モードの分離、対象ウィンドウ、CSS寸法、反復検出、分割範囲と画像結合への切り替え、デバッグ接続の後始末、連打・並行実行、保存エラーを検証します。連続撮影では目標間隔と負荷時の間引き、時刻付き一覧、途中停止、ZIP構造・CRC、保存失敗時の解放をモックで検証します。実ブラウザでの画像品質は以下で確認してください。

1. `tests/fixture.html` をブラウザで開き、ローカルファイルアクセスを許可します。
2. ページ途中までスクロールし、表示領域を撮影します。画像にブラウザ外枠や画面外の先頭・末尾がないことを確認します。
3. 同じ位置でページ全体を撮影します。画像に「START」「END」と右端のマーカーが含まれ、元のスクロール位置が保たれることを確認します。
4. ブラウザのズームを75%・125%に変更して両方撮影し、全体画像に同じ表示の反復・切れ・余白がないことを確認します。
5. 保存・コピーそれぞれのポップアップボタンとショートカットを試します。コピー後、画像を扱えるアプリへ貼り付けられること、異なるウィンドウでも対象が正しいことを確認します。
6. 「ページタイトルをコピー」にショートカットを割り当て、実行後にテキストエディターへ貼り付けると `PageShot キャプチャ確認ページ` になることを確認します。
7. 全体撮影後にデバッグ通知が消えること、失敗時にポップアップに理由が出ることを確認します。

8. 動きのあるページで「3秒・10fps・WebP」を撮影し、ZIP内に約30枚の連番画像と3枚の一覧があり、順序・時刻・動きが対応することを確認します。通常のスクリーンショットと同時実行できないことも確認します。
9. PNG、設定変更、ショートカット、カウントダウン中のキャンセル、撮影途中の停止、対象タブを閉じた場合を確認します。設定が再表示後も残り、終了後にタブの共有が解除されることを確認します。

## GitHub Releases用ZIP

ローカルでは次のコマンドで、実行に必要なファイルだけを含むZIPを生成できます。

```powershell
npm.cmd run package
```

出力先は `dist/korochin-pageshot-v1.2.0.zip` です。ZIPにはバージョン付きのトップフォルダがあり、展開後にそのフォルダをChrome / Edgeの「パッケージ化されていない拡張機能を読み込む」で指定できます。`tests`、GitHub Actions、開発用ファイルは含みません。

GitHubでは `manifest.json` と同じバージョンのタグをpushすると、テストと構文チェックを実行し、ZIPを添付したReleaseを自動作成します。

```powershell
git tag v1.2.0
git push origin v1.2.0
```

タグと `manifest.json` のバージョンが一致しない場合、誤ったリリースを防ぐためワークフローは失敗します。次回リリース時は、先に `manifest.json` と `package.json` のバージョンを同じ値へ更新してください。
